# Domain Concepts

## Project

The top-level organizational unit. A project contains files, sets, processing results, and sources as a directed acyclic graph (DAG). Projects appear as nodes on the home page and serve as the entry point to the graph workspace.

- Created with: name, description, position (x, y for home page placement)
- Each project has its own graph view
- Projects can be deleted (destroys all contained nodes)
- Projects track storage size

**Verified from:** `src/web.js` (`createProject`, `deleteProject`, `getProject`)

## File

A document stored in the system. Files have:
- `@rid` — ArcadeDB record ID (e.g., `#21:5`)
- `type` — Semantic type assigned by backend (e.g., `image`, `text`, `ocr.json`, `ner.json`)
- `extension` — File extension
- `label` — Display name (mutable by user)
- `path` — Server-relative path to file content
- `description` — User-editable description
- `entities` — Linked entity/tag list
- `edited` — Object present if file has been quick-edited (contains `task` field)
- `ref` — Boolean flag; if true, file is a reference (not editable)
- `thumbnail_version` — Cache-bust token for thumbnail URLs

Files are nodes in the project graph. They can be processing inputs or outputs.

**Verified from:** `src/components/displays/FileDisplayWrapper.vue`, `src/web.js`, `test/components/displays/VersionTools.spec.js`

## Set

A collection of files within a project. Sets appear as graph nodes and can be:
- **Flat:** Simple list of files
- **Grouped:** Files organized by source/origin

Sets support:
- Pagination (10 files per page in graph view, 24 in standalone)
- ZIP export (async job with status polling)
- Batch processing (run a cruncher on all files)
- File upload directly into set (single or multiple files; multi-file upload is Set-only, never onto the main desk)
- Thumbnail generation for contained files

Once a Set has been used as the input of a batch cruncher run, it is **locked**: no more files can be
added to it. There is no mechanism to re-run or extend a finished batch to cover files added afterwards,
so the backend rejects uploads into an already-processed Set (`Graph.hasSetBeenProcessed`, checked in
the upload route) and the UI hides the upload button in favor of a warning (`NodeCard.vue`'s `setLocked`,
backed by the `processed` flag on the Set's graph node data). See
[processing-crunchers.md](processing-crunchers.md#set-locking-after-batch-processing).

**Verified from:** `src/components/GraphDisplay.vue`, `src/components/displays/SetPanel.vue`, `src/web.js`, `src/components/NodeCard.vue`

## Source

An external data provider connected to a project. Known source types:
- `dspace7` — DSpace 7 repository
- `nextcloud` — Nextcloud file storage

Sources are created within a project and appear as graph nodes. They can be targets for batch processing.

**Verified from:** `src/components/GraphDisplay.vue` (node types), `src/components/SourceCreator.vue`, `src/web.js`

## Entity (Tag)

A typed label that can be linked to files. The entity system provides:
- **Types:** Defined by backend schema (retrieved via `getEntitySchema()`)
- **Instances:** Created per type with a label
- **Links:** Entities are linked to files (many-to-many), backed by the `TagLink` type on the backend (see
  MessyDesk's [graph-data-model.md](../../MessyDesk/wiki/architecture/graph-data-model.md))

The UI calls them "Tags" in the header tabs but "Entities" in the code and API. Tags can be manual
(`created_by: 'user'`) or machine-generated by a processing service's Autotag (`created_by: 'machine'`).
`EntitiesMain.vue`'s sidebar keeps the two visually separate: the plain per-type list (Tag, Person, ...)
only shows manual tags, real Autotag-created tags are browsed in their own "Machine tags" section grouped
by `(service_id, task)` (`web.getMachineTags`), and Faceted ROI-data results (see MessyDesk's
[glossary.md](../../MessyDesk/wiki/glossary.md)) are browsed in a separate "NER results" section that reads
each matching file's `ner.json` regions on demand (`web.getNerLabelGroups`/`getNerLabelMentions`) — there is
no separate region-scoped tag data model for that case. `TagsMain.vue` (since deleted) was not
wired into any route; it is dead code, not the component this behaviour lives in.

**Verified from:** `src/components/EntitiesMain.vue`, `src/web.js` (entity/tag methods)

## ROI (Region of Interest)

Rectangular selections on images. ROIs:
- Belong to a file within the context of a set (scoped by image RID + set RID)
- Are stored with pixel coordinates and original image dimensions
- Can be used as input for targeted processing (e.g., OCR a specific region)
- Have their own graph node type (`roi-set`)

**Verified from:** `src/web.js` (ROI methods), `src/components/GraphDisplay.vue` (ROI node handling)

## Cruncher/Process

A processing operation that transforms or analyzes files. See [processing-crunchers.md](processing-crunchers.md) for details.

## ServiceGroup

Admin-managed entity (`id`, `name`, `description`, `logo`) formalizing the `service_groups` values used
in `service.json` descriptors and on `User.service_groups` to gate which users can use a
service/task. Managed from the admin-only Service groups tab of the Admin page (`features/admin/ServiceGroupsTab.vue`); user membership is
edited inline from the Users tab in the same component. See the backend
[glossary](../../MessyDesk/wiki/glossary.md) and
[service-descriptor-format.md](../../MessyDesk/wiki/service-descriptor-format.md#service-groups) for
the full model, including the logo upload/resize flow.

## RID (Record ID)

OrientDB-style identifiers in format `#cluster:position` (e.g., `#21:5`). The frontend consistently strips the `#` prefix when embedding in URLs. The `@rid` field on returned objects always includes the `#`.

**Verified from:** `src/web.js` (all methods use `.replace('#','')`)

## Graph Relationships

The backend uses a directed graph (ArcadeDB). Key relationship patterns visible from the frontend:

- Project → File (contains)
- Project → Set (contains)
- Project → Source (has source)
- File → File (processing output, via Process node)
- Set → File (contains, with optional source grouping)
- Entity → File (tagged with)
- Process → File (produces)

**Inferred from:** `src/components/GraphDisplay.vue` (node double-click logic, `getIncomers` traversal), `src/web.js`
